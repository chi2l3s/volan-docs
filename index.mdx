Volan is a schema-first ORM for the JVM. You describe your data model once in a `schema.volan` file, and Volan generates a fully type-safe Kotlin and Java client at build time — complete query DSLs, row mappers, repositories, and write payloads. No runtime reflection, no hidden queries, no `NullPointerException` surprises.

## How Volan works

Volan follows a schema-first workflow: your `schema.volan` file is the single source of truth for your data model, and everything — your Kotlin/Java client, your type-safe DSLs, and your database migrations — is derived from it.

<Steps>
  <Step title="Write your schema">
    Define your models, fields, relations, and enums in a `schema.volan` file using a clean, Prisma-inspired syntax.

    ```prisma schema.volan
    datasource db {
      provider = "postgresql"
      url      = env("DATABASE_URL")
    }

    generator client {
      provider = "volan-kotlin"
      package  = "com.example.myapp"
      output   = "build/generated/volan"
    }

    model User {
      id        Int      @id @default(autoincrement())
      email     String   @unique
      name      String?
      posts     Post[]
      createdAt DateTime @default(now()) @map("created_at")
    }

    model Post {
      id       Int    @id @default(autoincrement())
      title    String
      author   User   @relation(fields: [authorId], references: [id])
      authorId Int
    }
    ```
  </Step>
  <Step title="Generate the client">
    Run code generation at build time. Volan produces type-safe entity classes, query DSLs, row mappers, and a `VolanClient` — all in plain Kotlin/Java with no runtime reflection.

    ```bash
    ./gradlew generateVolanClient
    ```
  </Step>
  <Step title="Connect and query">
    Instantiate the client with your database URL and start querying with full type safety. The compiler catches typos in field names, missing required columns, and invalid filter combinations.

    ```kotlin
    val db = BlogClient.builder()
        .url("jdbc:postgresql://localhost:5432/myapp")
        .username("postgres")
        .password(System.getenv("DB_PASSWORD"))
        .build()

    val users = db.user.findMany {
        where { email endsWith "@acme.com" }
        orderBy { createdAt.desc() }
        take = 20
    }
    ```
  </Step>
</Steps>

## Why Volan?

<CardGroup cols={2}>
  <Card title="No runtime reflection" icon="bolt">
    Row mapping is straight-line generated code. No classpath scanning, no proxy objects, no slow startup.
  </Card>
  <Card title="Java is first-class" icon="java">
    Every generated type is usable from Java without wrappers. No Kotlin-only types leak into the public API.
  </Card>
  <Card title="N+1 is impossible by design" icon="shield-check">
    Relation loading always uses one batched statement per relation level, not one query per row.
  </Card>
  <Card title="Errors that teach" icon="circle-info">
    Schema problems are reported with Rust-style code frames, carets pointing at the issue, and suggested fixes.
  </Card>
</CardGroup>

<Note>
  Volan is in active development, pre-1.0. PostgreSQL is fully supported today. MySQL, SQLite, and H2 are on the roadmap. See the [comparison page](/reference/comparison) for what's available now.
</Note>
