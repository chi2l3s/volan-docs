Nested writes let you create or link related records as part of a single `create` call, without manually wiring up foreign keys or writing multiple queries. Volan wraps all nested operations in one transaction, so either everything succeeds or nothing does.

<Note>
  Nested writes are only available inside `create {}`. The `createMany` operation does **not** support them — attempting a nested write inside a `row {}` block throws `VolanValidationException`.
</Note>

## The three nested write operations

There are three ways to handle a related record inside a `create`:

| Operation | Behaviour |
|---|---|
| `relation.create {}` | Inserts a new related record and links it to the parent. |
| `relation.connect {}` | Links an already-existing record to the parent by a unique filter. |
| `relation.connectOrCreate {}` | Connects an existing record if found, otherwise creates a new one. |

---

## `create` — insert a related record

Call `.create {}` on a relation field to insert a new child record at the same time as the parent. Field values for the new related record go directly inside the block.

### One-to-one relation

```kotlin
val user = db.user.create {
    email = "alice@acme.com"
    name  = "Alice"
    profile.create {
        bio = "Software engineer"
    }
}
// `user.profile` is populated with the newly created Profile
```

### One-to-many relation

```kotlin
val user = db.user.create {
    email = "alice@acme.com"
    name  = "Alice"
    posts.create {
        title = "Hello World"
        body  = "My first post"
    }
}
// The new Post is linked to `user` via the foreign key automatically
```

You can chain multiple `.create {}` calls to insert several related records at once:

```kotlin
val user = db.user.create {
    email = "alice@acme.com"
    name  = "Alice"
    posts.create { title = "Post One";   body = "..." }
    posts.create { title = "Post Two";   body = "..." }
    posts.create { title = "Post Three"; body = "..." }
}
```

## `connect` — link an existing record

Call `.connect {}` on a relation field when the related record already exists and you just want to establish the relationship. The filter inside `.connect {}` must resolve to a unique row.

```kotlin
val post = db.post.create {
    title  = "Using Volan"
    author.connect { id eq 42 }   // link to the existing User whose id is 42
}
```

<Tip>
  `.connect {}` only sets the foreign-key column on the new record — it does not modify the related record itself. If you need to update the related record at the same time, do so in a separate `update` call inside a [transaction](/writing/transactions).
</Tip>

---

## `connectOrCreate` — connect if exists, create if not

`.connectOrCreate {}` combines a lookup with a fallback insert. You provide the fields used to identify the related record; if a match is found it is linked, otherwise Volan creates it first and then links it.

This is especially useful for **many-to-many** relations where the related record (such as a tag) may or may not already exist.

```kotlin
val post = db.post.create {
    title  = "Tagged Post"
    author.connect { id eq 1 }
    tags.connectOrCreate { name = "kotlin" }
    tags.connectOrCreate { name = "orm" }
}
```

In this example, if a `Tag` with `name = "kotlin"` already exists it is linked to the post; if not, Volan creates it first and then links it. Both operations happen inside the same transaction as the outer `create`.

<Note>
  The fields you set in a `.connectOrCreate {}` block must cover at least one unique key on the related model so Volan can determine which row to look for. If no unique key is covered, Volan throws `VolanValidationException` before sending any SQL.
</Note>

---

## Combining nested operations

You can mix `.create`, `.connect`, and `.connectOrCreate` on different relation fields within a single `create` call:

```kotlin
val post = db.post.create {
    title  = "Comprehensive Post"

    // Connect to an existing author
    author.connect { id eq 1 }

    // Create a new Category inline
    category.create { name = "Engineering" }

    // connectOrCreate multiple tags
    tags.connectOrCreate { name = "volan" }
    tags.connectOrCreate { name = "kotlin" }
}
```

---

## Atomicity

All operations in a nested write — the top-level record and every nested `.create`, `.connect`, or `.connectOrCreate` — execute inside a single database transaction. If any part fails (for example, a `.connect {}` filter matches no row), the entire operation is rolled back and no partial data is persisted.

<Note>
  You do not need to wrap a nested write in an explicit `db.transaction {}` block to get this guarantee — Volan handles the transaction automatically. If you want to combine a nested write with other operations under the same transaction boundary, you can still nest it inside a manual `db.transaction {}`.
</Note>

## Relation types at a glance

  <Card title="One-to-one" icon="link">
    Use a single `.create {}` or `.connect {}` call on the relation field. No list syntax needed.
  </Card>
  <Card title="One-to-many" icon="list">
    Use one or more `.create {}` / `.connect {}` / `.connectOrCreate {}` calls on the relation field. Volan injects the foreign key for each child.
