Любой проект на Volan опирается на единственный источник истины — файл `schema.volan`, который описывает источники данных, настройки генератора кода, модели данных и перечисления. Инструменты Volan читают этот файл, чтобы проверить схему, сгенерировать типобезопасный код клиента и подготовить SQL миграций — поэтому поддержание его в актуальном состоянии — самый важный шаг в любом проекте.

## Структура файла

Файл `schema.volan` состоит из четырёх типов блоков. У каждого блока есть ключевое слово, имя и тело в фигурных скобках. Блоки могут идти в любом порядке, но по соглашению сначала идёт блок `datasource`, затем `generator`, а потом модели и перечисления.

```prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

generator client {
  provider = "volan-kotlin"
  package  = "com.example.myapp"
}

model User {
  id    Int    @id @default(autoincrement())
  email String @unique
}

enum Role {
  USER
  ADMIN
}
```

## Блок datasource

Блок `datasource` сообщает Volan, на какую СУБД ориентироваться и как к ней подключиться. Значение `url` чаще всего берётся из переменной окружения, чтобы учётные данные не попадали в систему контроля версий.

```prisma
datasource db {
  provider = "postgresql"   // postgresql | mysql | sqlite
  url      = env("DATABASE_URL")
}
```

Поддерживаемые провайдеры: `"postgresql"`, `"mysql"` и `"sqlite"`.

## Блок generator

Блок `generator` определяет, какой код создаёт Volan и куда его кладёт.

```prisma
generator client {
  provider     = "volan-kotlin"
  package      = "com.example.myapp"
  output       = "build/generated/volan"
  javaFriendly = true
}
```

| Параметр | Описание |
| --- | --- |
| `provider` | Генератор для запуска. Для проектов Kotlin/JVM используйте `"volan-kotlin"`. |
| `package` | Корневое имя пакета для всех сгенерированных классов. |
| `output` | Каталог, куда записываются сгенерированные исходники. |
| `javaFriendly` | При значении `true` генерирует дополнительные совместимые с Java методы доступа. |

## Запуск форматтера

В комплекте с Volan идёт встроенный форматтер: он нормализует пробельные символы, выравнивает имена полей и типы по колонкам и выравнивает знаки `=` внутри конфигурационных блоков. Запускайте его из корня проекта:

```bash
volan format
```

Форматтер перезаписывает `schema.volan` на месте. И `// комментарии`, и `/// док-комментарии` сохраняются там, где их оставил автор, как и пустые строки, группирующие поля. `/// Док-комментарии` дополнительно переносятся в сгенерированный код Kotlin как KDoc.

## Комментарии и док-комментарии

```prisma
// Этот комментарий сохраняется форматтером.

/// Этот док-комментарий сохраняется и попадает в сгенерированный класс Kotlin.
model Post {
  id Int @id @default(autoincrement())
}
```

Используйте док-комментарии `///` на моделях и полях, чтобы добавить KDoc к сгенерированным классам и свойствам. Используйте `//` для заметок, которые должны остаться в файле схемы, но не нужны в сгенерированном коде.

## Диагностика ошибок

Если в схеме есть ошибка, Volan выводит структурированную диагностику с указанием точного места в файле:

```text
error[E0104]: expected a field type
 ┌─ schema.volan:2:9
 │
2│   email @unique
 │         ^ found `@`
 │
 = help: a field is written as `name Type`, for example `email String`
```

Диагностика включает код ошибки, указатель на файл/строку/колонку, краткое объяснение и, по возможности, подсказку `help`. Ошибки валидации всегда обнаруживаются до начала генерации кода или миграций.

<Note>
  Volan проверяет всю схему целиком до того, как сгенерировать хоть какой-то код. Если хотя бы одна модель, связь или атрибут некорректны, весь запуск прерывается и ни один файл не записывается.
</Note>

### Коды синтаксических ошибок (E0001–E0121)

Эти коды возникают, когда документ синтаксически некорректен — схему вообще не удаётся разобрать.

| Код | Значение |
| --- | --- |
| `E0001` | Незакрытый строковый литерал |
| `E0002` | Неверная escape-последовательность |
| `E0003` | Неожиданный символ |
| `E0004` | Блочные комментарии не поддерживаются |
| `E0005` | Некорректный числовой литерал |
| `E0100` | Неизвестное объявление верхнего уровня |
| `E0101` | Ожидалось имя |
| `E0102` | Ожидался `{` |
| `E0103` | Незакрытый блок |
| `E0104` | Ожидался тип поля |
| `E0105` | Ожидался `=` |
| `E0106` | Ожидалось значение |
| `E0107` | Незакрытый список аргументов |
| `E0108` | Незакрытый список |
| `E0109` | Списочный тип не может быть опциональным |
| `E0110` | Вложенные списочные типы не поддерживаются |
| `E0111` | Повторяющийся маркер `?` |
| `E0112` | `@` использован вместо `@@` или наоборот |
| `E0113` | Ожидалось имя атрибута |
| `E0114` | Ожидалось имя после `.` |
| `E0115` | Именованный аргумент без значения |
| `E0116` | Неожиданный токен на верхнем уровне |
| `E0117` | Модель без полей |
| `E0118` | Перечисление без значений |
| `E0119` | Свойство конфигурации без значения |
| `E0120` | Атрибут в блоке `datasource` или `generator` |
| `E0121` | Неожиданный токен внутри блока |

`W0001` — предупреждение о док-комментарии, который не удаётся привязать ни к одному объявлению.

### Коды семантических ошибок (E0200–E0234)

Эти коды возникают после успешного разбора, когда схема структурно верна, но логически некорректна.

| Код | Значение |
| --- | --- |
| `E0200` | Два объявления с одинаковым именем |
| `E0201` | Неизвестный тип поля |
| `E0202` | Дублирующееся поле, значение перечисления или свойство |
| `E0203` | Отсутствует блок `datasource` |
| `E0204` | Больше одного блока `datasource` |
| `E0205` | Неизвестный провайдер базы данных |
| `E0206` | Отсутствует обязательное свойство блока |
| `E0207` | Неизвестное свойство блока |
| `E0208` | Свойство или аргумент неверного вида |
| `E0209` | Модель без первичного ключа |
| `E0210` | Первичный ключ объявлен дважды |
| `E0211` | Поле не может быть частью первичного ключа |
| `E0212` | Неизвестный атрибут |
| `E0213` | Неизвестный аргумент атрибута |
| `E0214` | Отсутствует аргумент атрибута |
| `E0215` | Атрибут недопустим для этой цели |
| `E0216` | Атрибут применён дважды |
| `E0217` | `@default` не подходит полю |
| `E0218` | `@updatedAt` на поле, которое он не может поддерживать |
| `E0219` | Атрибут ссылается на неизвестное поле |
| `E0220` | У связи нет парного поля на другой модели |
| `E0221` | Несколько полей связи могут составить пару |
| `E0222` | `fields` и `references` не согласуются |
| `E0223` | Внешний ключ объявлен не на той стороне, на обеих или ни на одной |
| `E0224` | `references` не идентифицирует строку |
| `E0225` | У внешнего ключа и целевого поля разные типы |
| `E0226` | Референциальное действие неизвестно или невозможно |
| `E0227` | Две модели или поля отображаются в одно имя в базе |
| `E0228` | Каскад замыкается сам на себя _(предупреждение)_ |
| `E0229` | `@unique` на поле, которое его не допускает |
| `E0230` | Ограничение объявлено без полей |
| `E0231` | Неизвестное пространство имён атрибута |
| `E0232` | Модель требует строку самой себя |
| `E0233` | Внешний ключ связи один-к-одному не уникален |
| `E0234` | URL подключения записан прямо в схему _(предупреждение)_ |

## API разбора и форматирования

Для интеграций с инструментами и сборкой Volan предоставляет стабильные JVM-объекты `SchemaParser` и `SchemaFormatter`.

### `SchemaParser`

```kotlin
// Разобрать и просмотреть диагностику
val result = SchemaParser.parse("schema.volan", File("schema.volan").readText())
if (result.hasErrors) {
    print(result.render())  // выводит читаемую диагностику
}

// Разобрать или бросить исключение при ошибке
val document = SchemaParser.parseOrThrow(source)
```

| Метод | Описание |
| --- | --- |
| `SchemaParser.parse(name, text)` | Разбирает `text` и возвращает объект результата с `hasErrors`, `render()` и списком диагностик. Никогда не бросает исключений. |
| `SchemaParser.parseOrThrow(source)` | Разбирает и возвращает документ либо бросает исключение, если в схеме есть ошибки. Сообщение исключения — полный вывод диагностики. |

### `SchemaFormatter`

```kotlin
// Форматирование напрямую из текста
val formatted = SchemaFormatter.format("schema.volan", File("schema.volan").readText())

// Форматирование ранее разобранного документа
val formatted = SchemaFormatter.format(document)
```

| Метод | Описание |
| --- | --- |
| `SchemaFormatter.format(name, text)` | Разбирает и возвращает канонически отформатированный текст как `String`. Бросает исключение, если в схеме есть ошибки. |
| `SchemaFormatter.format(document)` | Форматирует уже разобранный документ и возвращает результат как `String`. |
