Модель в Volan представляет таблицу базы данных и становится основой для сгенерированного типобезопасного класса клиента. Модель объявляется ключевым словом `model`, получает имя в PascalCase, а её поля перечисляются в фигурных скобках. У каждой модели должно быть как минимум одно поле, служащее первичным ключом.

## Базовый синтаксис модели

```prisma
model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique
  name      String?
  createdAt DateTime @default(now())
}
```

Каждая строка внутри блока — это объявление поля: имя, тип и ноль или более атрибутов. Имя модели становится именем класса в сгенерированном коде, а имена полей — свойствами.

## Кардинальность полей

У каждого поля есть кардинальность, которая определяет, является ли значение обязательным, допускает ли `null` или является коллекцией.

| Синтаксис | Значение | Сгенерированный тип Kotlin |
| --- | --- | --- |
| `String` | Обязательное — всегда должно иметь значение | `String` |
| `String?` | Опциональное — может быть `null` | `String?` |
| `String[]` | Список — хранится как колонка-массив | `List<String>` |

```prisma
model Article {
  id       Int      @id @default(autoincrement())
  title    String           // обязательное
  subtitle String?          // опциональное (nullable)
  tags     String[]         // список (колонка-массив)
}
```

<Note>
  Списочные поля (`[]`) поддерживаются через колонки-массивы PostgreSQL. В MySQL и SQLite используйте вместо них сериализованное JSON-поле или связующую таблицу.
</Note>

## Маппинг модели на произвольное имя таблицы

По умолчанию Volan сопоставляет модель с таблицей, имя которой — это имя модели в нижнем регистре и snake\_case. Чтобы переопределить это, используйте `@@map`:

```prisma
model User {
  id    Int    @id @default(autoincrement())
  email String @unique

  @@map("users")
}
```

Это особенно полезно, когда в вашей базе принято соглашение об именовании, отличающееся от умолчаний Volan, или когда вы накладываете Volan на существующую схему.

## Составной первичный ключ

Когда ни одно поле по отдельности не идентифицирует строку однозначно, объявите составной первичный ключ через `@@id`:

```prisma
model PostTag {
  postId Int
  tagId  Int

  @@id([postId, tagId])
}
```

Поля, перечисленные в `@@id`, не должны дополнительно нести атрибут `@id`.

## Уникальные ограничения

Используйте `@unique` для отдельного поля или `@@unique` для комбинации полей.

```prisma
model User {
  id       Int    @id @default(autoincrement())
  email    String @unique
}

model Membership {
  userId Int
  orgId  Int

  @@unique([userId, orgId])
}
```

Сгенерированный клиент предоставляет вспомогательные методы вроде `findByEmail` для полей с `@unique` и гарантирует уникальность на уровне базы данных в обоих вариантах.

## Индексы

Добавьте составной индекс через `@@index`, чтобы ускорить запросы с фильтрацией или сортировкой по нескольким колонкам:

```prisma
model Post {
  id          Int      @id @default(autoincrement())
  authorId    Int
  publishedAt DateTime

  @@index([authorId, publishedAt])
}
```

Можно определить столько блоков `@@index`, сколько нужно. Volan выпускает соответствующие выражения `CREATE INDEX` во время миграции.

## Полнотекстовые индексы

Для баз данных, которые это поддерживают (PostgreSQL с `pg_trgm`, MySQL), объявите полнотекстовый индекс через `@@fulltext`:

```prisma
model Article {
  id      Int    @id @default(autoincrement())
  title   String
  body    String

  @@fulltext([title, body])
}
```

<Warning>
  `@@fulltext` не поддерживается в SQLite. При использовании с провайдером `sqlite` Volan сообщит об ошибке валидации.
</Warning>

## Игнорирование модели

Пометьте модель атрибутом `@@ignore`, чтобы полностью исключить её из сгенерированного клиента. Volan всё равно проверит её поля, но ни класс, ни методы запросов для неё созданы не будут.

```prisma
model LegacyAuditLog {
  id      Int    @id
  payload String

  @@ignore
}
```

Это удобно для таблиц, которые есть в базе, но не управляются кодом вашего приложения.

## Полный пример

Следующая модель объединяет большинство возможностей, описанных на этой странице:

```prisma
model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique @db.VarChar(320)
  name      String?
  role      Role     @default(USER)
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt      @map("updated_at")
  posts     Post[]
  profile   Profile?

  @@index([email, createdAt])
  @@map("users")
}
```

<Tip>
  Держите имена моделей в единственном числе и в PascalCase (`User`, а не `Users` или `user`). Логика образования множественного числа в Volan опирается на это соглашение при именовании вспомогательных методов.
</Tip>
