Volan — это schema-first ORM для JVM, которая переносит опыт разработки в стиле Prisma в мир Kotlin и Java. Вы описываете всю модель данных в единственном файле `schema.volan`, запускаете генератор кода на этапе сборки и получаете полностью типобезопасный клиент — без аннотаций, разбросанных по доменным классам, без рефлексии в горячем пути и без скрытых запросов, прячущихся за ленивыми прокси.

## Основной рабочий цикл

Любой проект на Volan следует одному и тому же циклу из трёх шагов: написать схему, сгенерировать клиент и писать запросы с полной типобезопасностью.

<Steps>
  <Step title="Опишите модель данных">
    Напишите файл `schema.volan` на синтаксисе, похожем на Prisma. Определите источник данных, модели, перечисления и связи в одном месте.

    ```prisma schema.volan
    datasource db {
      provider = "postgresql"
      url      = env("DATABASE_URL")
    }
    
    generator client {
      provider     = "volan-kotlin"
      package      = "com.example.blog"
      output       = "build/generated/volan"
      javaFriendly = true
    }
    
    model User {
      id        Int      @id @default(autoincrement())
      email     String   @unique
      name      String?
      posts     Post[]
      createdAt DateTime @default(now())
    
      @@map("users")
    }
    ```
  </Step>
  <Step title="Запустите генератор кода">
    Задача `VolanGenerator` выполняется на этапе сборки и записывает класс клиента (названный по имени выходного пакета) в ваш каталог сборки. Никаких обработчиков аннотаций и weaving в рантайме.

    ```bash
    ./gradlew generateVolanClient
    ```
  </Step>
  <Step title="Пишите типобезопасные запросы">
    Используйте сгенерированный клиент. Компилятор поймает опечатки в именах полей, пропущенные `where` и несовпадающие типы — ещё до обращения к базе данных.

    ```kotlin Kotlin
    val users = db.user.findMany {
        where {
            email endsWith "@acme.com"
            createdAt gt Instant.now().minus(30.days)
        }
        include { posts { take = 5 } }
        orderBy { createdAt.desc() }
        take = 20
    }
    ```

    ```java Java
    List<User> users = db.user().findMany(q -> q
            .where(w -> w.email().endsWith("@acme.com"))
            .include(i -> i.posts(p -> p.take(5)))
            .orderBy(User_.CREATED_AT.desc())
            .take(20));
    ```
  </Step>
</Steps>

## Чем Volan отличается от других

Volan создавался, чтобы решить самые частые болевые точки существующих ORM для JVM. Таблица ниже показывает, какое место он занимает.

|  | Volan | Hibernate / JPA | Exposed | JOOQ |
| --- | --- | --- | --- | --- |
| Источник истины | Файл схемы | Классы с аннотациями | Объекты таблиц на Kotlin | База данных |
| Типобезопасные запросы | Сгенерированный DSL | Строки JPQL / Criteria | DSL | Сгенерированный DSL |
| Рефлексия в рантайме | Нет на пути маппинга | Широко используется | Частично | Нет |
| Декларативные миграции | Встроены | Внешние (Flyway / Liquibase) | Внешние | Внешние |
| Вложенная запись | Встроена | Каскады | Вручную | Вручную |
| API с прицелом на Java | Да, покрыто тестами на Java | Да | Неудобное | Да |
| Сюрпризы ленивой загрузки | Исключены по дизайну | Часты | Явная загрузка | Неприменимо |

<CardGroup cols={2}>
  <Card title="Никакой рефлексии в рантайме" icon="bolt">
    Маппинг строк — это прямолинейный сгенерированный код. Нет ни прокси, ни контекстов персистентности, ни магического сканирования `@Entity` при старте.
  </Card>

  <Card title="Никаких скрытых запросов" icon="eye">
    Связи никогда не загружаются лениво. Каждая нужная связь должна быть указана в блоке `include`. Проблема N\+1 структурно невозможна — и набор тестов проверяет количество запросов.
  </Card>

  <Card title="Java — равноправная цель" icon="coffee">
    Публичный API проверяется набором тестов на языке Java. Никакие Kotlin-специфичные типы не протекают в Java-код, и никаких параметров `Continuation`.
  </Card>

  <Card title="Ошибки, которые учат" icon="circle-info">
    Проблемы в схеме выводятся с фрагментом кода, указателем на проблемный токен и подсказкой, как исправить — ещё до того, как генератор запишет хоть один файл.
  </Card>
</CardGroup>

## Поддерживаемые базы данных

На сегодня основная поддерживаемая СУБД — PostgreSQL, с полным покрытием интеграционными тестами. MySQL, MariaDB, SQLite и H2 — следующие цели к релизу 1.0, именно в таком порядке приоритета.

<Note>
  В текущем релизе полностью поддерживается только PostgreSQL. Остальные модули из BOM — `volan-dialect-mysql`, `volan-dialect-sqlite`, `volan-dialect-h2`, `volan-coroutines` и `volan-migrate` — зарезервированы для будущих этапов. Полный список модулей см. на странице [Установка](/ru/installation).
</Note>

## Текущий статус

Volan находится в стадии до 1.0 и активно разрабатывается. Проект развивается публично, этап за этапом. Он пока не опубликован в Maven Central — сегодня его можно использовать, собрав из исходного кода или установив в локальный репозиторий Maven.

<Warning>
  Пока проект не достиг версии 1.0, API может меняться между релизами. Перед обновлением в продакшен-проекте сверяйтесь с [ROADMAP](https://github.com/thirtyeighttwentysix/volan/blob/main/ROADMAP.md) и [CHANGELOG](https://github.com/thirtyeighttwentysix/volan).
</Warning>
