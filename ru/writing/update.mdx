Операции обновления Volan позволяют изменять конкретные поля существующих строк, не затрагивая то, что вы явно не указали. Независимо от того, меняете ли вы одну запись или массово патчите тысячи строк, операции `update` и `updateMany` сохраняют запись точной и предсказуемой.

## Обновление одной записи

Используйте `db.<model>.update {}`, чтобы изменить одну строку и получить обновлённую сущность. Вызов требует два блока: фильтр `where {}`, определяющий целевую строку, и `data {}` со списком полей, которые нужно изменить.

```kotlin
val user = db.user.update {
    where { id eq 42 }
    data {
        name = "Alice Updated"
    }
}
```

Возвращаемый `user` отражает состояние строки после обновления, включая поля, которые уже были установлены, и любые временные метки `@updatedAt`, подставленные Volan.

### Частичные обновления — меняются только затронутые поля

Поля, которые вы опустили в `data {}`, остаются в базе точно такими, как были. Volan генерирует выражение `SET`, содержащее только явно присвоенные колонки. Это означает, что можно безопасно обновить одно поле в записи с десятками колонок, не рискуя случайной потерей данных.

```kotlin
// Обновляется только колонка `role` — остальные не затронуты
val user = db.user.update {
    where { id eq 42 }
    data {
        role = Role.ADMIN
    }
}
```

<Tip>
  Поскольку обновления по умолчанию частичные, вам никогда не нужно сначала загружать запись, чтобы повторно передать её текущие значения. Передавайте только то, что должно измениться.
</Tip>

### Автоматическая подстановка `@updatedAt`

Поля с `@updatedAt` в схеме обновляются Volan автоматически при каждом вызове `update` и `updateMany`. Добавлять их в `data {}` не нужно — Volan сам подставляет текущую временную метку UTC в SQL-выражение.

### Бросает исключение, когда запись не найдена

Если фильтр `where {}` не находит ни одной строки, `update` бросает `VolanNotFoundException`. Это мешает молчаливым пустым операциям остаться незамеченными в логике приложения.

<Warning>
  Всегда обрабатывайте `VolanNotFoundException` в путях, где существование записи не гарантировано. Если нужна семантика «создать-или-обновить», используйте `upsert` (см. [Создание записей](/ru/writing/create)).
</Warning>

### Нарушения уникальных ограничений

Если обновлённые значения нарушают уникальный индекс, Volan бросает `VolanUniqueConstraintException`. Исключение несёт имя нарушенного ограничения, если база его возвращает.

## Обновление многих записей

`updateMany {}` применяет одни и те же изменения из `data {}` ко всем строкам, подходящим под фильтр `where {}`, и возвращает количество затронутых строк как `Long`.

```kotlin
val count = db.user.updateMany {
    where { role eq Role.USER }
    data  { role = Role.ADMIN }
}
// count == количество строк, у которых изменилась роль
```

<Note>
  `updateMany` не возвращает обновлённые сущности — только количество строк. Если нужны записи после обновления, выполните `findMany` с тем же фильтром после обновления или выполните все внутри [транзакции](/ru/writing/transactions).
</Note>

### Ограничение области фильтра

Блок `where {}` в `updateMany` поддерживает те же операторы, что и `findMany`: равенство, сравнения, логические комбинаторы (`and`, `or`, `not`) и фильтры по связям. Всегда проверяйте, что ваш фильтр возвращает нужный набор, перед тем как запустить его в проде.

<Warning>
  Вызов `updateMany` без блока `where {}` или с фильтром, подходящим ко всем строкам, обновит всю таблицу. Сначала проверяйте фильтр через `findMany`.
</Warning>
