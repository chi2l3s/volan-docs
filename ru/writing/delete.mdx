Volan предоставляет две операции удаления: `delete` для удаления одной известной записи и `deleteMany` для удаления всех строк, подходящих под фильтр. Обе операции учитывают раскрытые в схеме каскадные правила, поэтому связанные записи чистятся последовательно без дополнительного кода в приложении.

## Удаление одной записи

Используйте `db.<model>.delete {}`, чтобы удалить одну строку по уникальному фильтру и получить удалённую сущность. Возврат сущности позволяет подтвердить, что именно было удалено, — это полезно для аудита или пост-обработки.

```kotlin
val user = db.user.delete {
    where { id eq 42 }
}
// `user` — сущность в том виде, какая была непосредственно до удаления
```

### Бросает исключение, когда запись не найдена

Если фильтр `where {}` не находит ни одной строки, `delete` бросает `VolanNotFoundException`. Это делает код честным: отсутствующая запись трактуется как исключительная ситуация, а не как молчаливая пустая операция.

<Warning>
  Обрабатывайте `VolanNotFoundException` везде, где существование записи не гарантировано, например, когда ID пришёл из пользовательского ввода или из внешней системы.
</Warning>

## Удаление многих записей

`deleteMany {}` удаляет каждую строку, подходящую под фильтр `where {}`, и возвращает количество удалённых строк как `Long`.

```kotlin
val count = db.user.deleteMany {
    where { createdAt lt Instant.now().minus(30, ChronoUnit.DAYS) }
}
// count == количество удалённых строк
```

<Warning>
  Опускание блока `where {}` или фильтр, подходящий ко всем строкам, удалит **все записи в таблице**. Всегда сначала проверяйте фильтр через `findMany`, прежде чем запускать широкий `deleteMany` в проде.
</Warning>

### Безопасное ограничение области

Блок `where {}` поддерживает весь набор операторов фильтрации, доступный в `findMany`: равенство, сравнения, диапазоны дат, логические комбинаторы и фильтры по связям. Обычный паттерн — сначала посмотреть, какие строки будут удалены, перед тем как запустить удаление:

```kotlin
// 1. Предварительный просмотр — тот же фильтр, без изменений
val affected = db.user.findMany {
    where { createdAt lt Instant.now().minus(30, ChronoUnit.DAYS) }
}
println("Сейчас будет удалено пользователей: ${affected.size}")

// 2. Удаление — только после подтверждения
val count = db.user.deleteMany {
    where { createdAt lt Instant.now().minus(30, ChronoUnit.DAYS) }
}
```

## Каскадное удаление

Когда ваша схема объявляет `onDelete: Cascade` на связи, база автоматически удаляет зависимые строки, когда удаляется родитель. Volan учитывает такое поведение — вам не нужно писать дополнительные вызовы delete для дочерних моделей.

```prisma
model Post {
  id       Int  @id @default(autoIncrement())
  author   User @relation(fields: [authorId], references: [id], onDelete: Cascade)
  authorId Int
}
```

С такой схемой удаление записи `User` также удаляет все его записи `Post` в той же операции базы.

<Note>
  Каскадное поведение обеспечивается базой, а не рантаймом Volan. Если вы используете базу без поддержки внешних ключей (или ограничения отключены), каскады не сработают. Проверьте вывод миграции, чтобы убедиться, что ограничение было создано.
</Note>

<Tip>
  Для сложной логики очистки, которую каскады не могут выразить — например, удаление записей кросс-модельно — заверните удаления в [транзакцию](/ru/writing/transactions), чтобы они выполнялись атомарно.
</Tip>
