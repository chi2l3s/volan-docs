API записи Volan даёт типобезопасный способ вставлять данные в базу, управляемый схемой. Операции `create` и `createMany` покрывают всё — от вставки одной строки до массовой загрузки многих записей, причём Volan валидирует данные ещё до того, как будет отправлен SQL.

## Создание одной записи

Используйте `db.<model>.create {}`, чтобы вставить одну строку и получить полностью заполненную сущность. Значения полей вы задаёте прямо внутри блока `create {}` как типизированные присвоения свойств. Каждое поле из схемы доступно как типизированное свойство, поэтому компилятор ловит опечатки и несовпадения типов во время сборки.

```kotlin
val user = db.user.create {
    email = "alice@acme.com"
    name = "Alice"
    role = Role.USER
}
```

Возвращаемый объект `user` содержит все поля модели, включая те, которые вы не задали вручную.

### Что Volan заполняет автоматически

Поля, помеченные `@id`, `@default` или `@updatedAt`, обрабатываются Volan или самой базой — вы никогда не выставляете их вручную внутри `create {}`.

| Аннотация | Поведение |
| --- | --- |
| `@id` с `autoIncrement()` | Значение назначает база; Volan считывает его обратно и заполняет сущность. |
| `@default(...)` | Применяется заявленное выражение по умолчанию, когда поле опущено. |
| `@updatedAt` | Volan автоматически подставляет текущую временную метку при каждой записи. |

<Note>
  Попытка присвоить значение полю `@id` или `@default` внутри `create {}` приведёт к ошибке во время компиляции — сгенерированный DSL Volan намеренно не включает таких сеттеров.
</Note>

### Обязательные и опциональные поля

Поле **обязательно** в `create`, если у него нет `@default`, оно не nullable и не является полем-связью, управляемым в другом месте. Если пропустить обязательное поле, Volan бросает `VolanValidationException` ещё до отправки SQL в базу.

```kotlin
// Отсутствует `email` — мгновенно бросает VolanValidationException
val user = db.user.create {
    name = "Alice"
    // email обязателен, но отсутствует
}
```

<Warning>
  `VolanValidationException` бросается на клиентской стороне, поэтому частичная строка не вставляется. Оборачивать неудавшийся `create` в rollback не нужно.
</Warning>

Опциональные поля (nullable или с `@default`) можно свободно опускать — Volan отправит для них `NULL` или значение по умолчанию.

### Нарушения уникальных ограничений

Если переданные значения нарушают уникальный индекс (например, вставка дубликата email), Volan бросает `VolanUniqueConstraintException`. Исключение несёт имя нарушенного ограничения, если база его возвращает.

## Создание многих записей сразу

`createMany {}` вставляет несколько строк одним выражением и возвращает количество вставленных строк как `Long`. Каждая строка описывается блоком `row {}`, который следует тем же правилам типизации, что обычный `create`.

```kotlin
val count = db.user.createMany {
    row { email = "alice@acme.com"; name = "Alice" }
    row { email = "bob@acme.com";   name = "Bob"   }
}
// count == 2L
```

<Note>
  `createMany` **не** поддерживает вложенные записи. Добавление блока связи внутри `row {}` бросает `VolanValidationException` во время выполнения. Если нужно создавать связанные записи вместе с родителем, используйте `create {}` с вложенной записью — см. [Вложенные записи](/ru/writing/nested-writes).
</Note>

### Когда предпочитать `createMany`

<CardGroup cols={2}>
  <Card title="Массовые вставки" icon="bolt">
    `createMany` группирует все строки в одно SQL-выражение, что значительно быстрее цикла из отдельных `create`.
  </Card>

  <Card title="Заполнение данных" icon="database">
    Используйте `createMany` в seed-скриптах миграций или тестовых фикстурах, когда нужно быстро вставить много строк и созданные сущности обратно не нужны.
  </Card>
</CardGroup>

### Возвращаемое значение

`createMany` возвращает число `Long`, а не список сущностей. Если нужны созданные записи, выполните `findMany` с фильтром по только что вставленным значениям или перейдите на отдельные вызовы `create` внутри [транзакции](/ru/writing/transactions).
