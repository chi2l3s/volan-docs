Fields are the building blocks of a Volan model. Each field declaration names a column in the underlying table, assigns it a scalar type, and optionally attaches attributes that control behaviour such as primary keys, default values, and column naming. This page covers every scalar type Volan supports and all field-level attributes you can apply.

## Scalar types

Volan provides a fixed set of scalar types that map predictably to Kotlin and Java types in the generated client.

| Volan type | Kotlin type | Java type | Notes |
|---|---|---|---|
| `String` | `String` | `String` | Variable-length text |
| `Int` | `Int` | `int` | 32-bit signed integer |
| `Long` | `Long` | `long` | 64-bit signed integer |
| `Float` | `Float` | `float` | Single-precision IEEE 754 |
| `Double` | `Double` | `double` | Double-precision IEEE 754 |
| `Decimal` | `java.math.BigDecimal` | `BigDecimal` | Arbitrary-precision decimal |
| `Boolean` | `Boolean` | `boolean` | `true` / `false` |
| `DateTime` | `java.time.Instant` | `Instant` | Timestamp with timezone |
| `Date` | `java.time.LocalDate` | `LocalDate` | Date only, no time component |
| `Time` | `java.time.LocalTime` | `LocalTime` | Time only, no date component |
| `Json` | `volan.Json` | `Json` | JSON value; access raw string via `.raw` |
| `Bytes` | `ByteArray` | `byte[]` | Binary data |
| `Uuid` | `java.util.UUID` | `UUID` | UUID stored as `uuid` or `char(36)` |

### Json fields

The `Json` type stores arbitrary JSON in a text or `jsonb` column. In generated code, Volan wraps the value in a `Json` object that exposes the raw string:

```kotlin
val payload: Json = post.metadata
println(payload.raw) // e.g. {"key":"value"}
```

You are responsible for serialising and deserialising the content; Volan does not parse the JSON.

## Field cardinality

Append a `?` to make a field nullable, or `[]` to make it a list (array column):

```prisma
model Document {
  id       Int      @id @default(autoincrement())
  title    String           // required
  summary  String?          // optional — Kotlin type is String?
  keywords String[]         // list — Kotlin type is List<String>
}
```

## Field-level attributes

Attributes are written after the type, prefixed with `@`. Multiple attributes are separated by spaces.

### `@id`

Marks the field as the primary key. Every model must have exactly one `@id` field or one `@@id` block attribute.

```prisma
model Product {
  id Int @id @default(autoincrement())
}
```

### `@default(value)`

Sets a default value for the field when no value is supplied on insert. Volan supports the following default expressions:

| Expression | Meaning |
|---|---|
| `autoincrement()` | Database auto-increment sequence (integer primary keys) |
| `now()` | Current timestamp at insert time |
| A literal | `@default(0)`, `@default("")`, `@default(true)` |
| An enum value | `@default(USER)` — must match a value in the referenced enum |

```prisma
model Order {
  id        Int      @id @default(autoincrement())
  total     Decimal  @default(0)
  status    Status   @default(PENDING)
  createdAt DateTime @default(now())
}
```

### `@unique`

Creates a unique constraint on this field. Volan also generates a `findByFieldName` helper on the client for every `@unique` field.

```prisma
model User {
  id    Int    @id @default(autoincrement())
  email String @unique
}
```

### `@updatedAt`

Automatically updates this field to the current timestamp whenever the row is updated. The field must be of type `DateTime`.

```prisma
model Post {
  id        Int      @id @default(autoincrement())
  updatedAt DateTime @updatedAt
}
```

<Note>
  `@updatedAt` is handled at the Volan client level, not in the database. The generated code injects the current `Instant` into every `UPDATE` statement for this field.
</Note>

### `@map("column_name")`

Maps the field to a database column whose name differs from the field name. The field name in generated Kotlin code stays unchanged.

```prisma
model User {
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt      @map("updated_at")
}
```

### `@ignore`

Excludes this field from the generated client. The column still exists in the database, but Volan will not read or write it.

```prisma
model User {
  id           Int    @id @default(autoincrement())
  passwordHash String @ignore
}
```

### `@db.*` — provider-specific type hints

Use the `@db` namespace to pass a provider-specific type hint to the migration engine. This lets you control the exact column type emitted in DDL without affecting the Kotlin type.

```prisma
model User {
  email String @db.VarChar(320)
  bio   String @db.Text
}
```

```prisma
model Metric {
  value Decimal @db.Decimal(18, 6)
}
```

Available hints depend on the provider. Dialect-specific validation is enforced at migration time. Specifying a hint that is not valid for the active provider produces a validation error.

<Tip>
  You can combine multiple attributes on a single field. Write them in the order `@id`, `@default`, `@unique`, `@db.*`, `@map` for readability — Volan does not enforce ordering, but the formatter will normalise it.
</Tip>

## Putting it all together

```prisma
model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique @db.VarChar(320)
  name      String?
  bio       String?  @db.Text
  score     Decimal  @default(0) @db.Decimal(10, 2)
  metadata  Json?
  avatar    Bytes?
  publicId  Uuid     @unique @default(uuid())
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt      @map("updated_at")
}
```
