Volan's schema compiler emits structured diagnostics whenever it encounters a problem in your `.volan` schema file. Every diagnostic has a unique code, a human-readable message, and a source location. This page lists every code organised by phase, so you can quickly understand what went wrong and how to correct it.

Diagnostics follow a Rust-style format with the code and message on the first line, then a file/line/column pointer and an inline annotation:

```
error[E0104]: field declaration is missing its type
  --> schema.volan:12:5
   |
12 |   name
   |   ^^^^ expected a type here, e.g. `name String`
```

## Lexer Errors (E000x)

Lexer errors occur before any parsing takes place. The schema compiler cannot tokenise the input and will not attempt to continue.

<Accordion title="E0001 — UNTERMINATED_STRING">

**Cause:** A string literal opened with `"` is not closed before the end of the line.

```volan
// ❌ missing closing quote
datasource db {
  url = "postgresql://localhost/mydb
}
```

**Fix:** Close the string on the same line.

```volan
// ✅
datasource db {
  url = "postgresql://localhost/mydb"
}
```

</Accordion>

<Accordion title="E0002 — INVALID_ESCAPE_SEQUENCE">

**Cause:** A string literal contains a backslash followed by a character that is not a recognised escape (`\n`, `\t`, `\\`, `\"`, `\r`).

```volan
// ❌ \x is not a valid escape
@default("\xAB")
```

**Fix:** Use a valid escape sequence or remove the backslash.

</Accordion>

<Accordion title="E0003 — UNEXPECTED_CHARACTER">

**Cause:** The lexer encountered a character that is not valid anywhere in a Volan schema, such as `$`, `%`, or a bare `#`.

**Fix:** Remove or replace the character. If you intended a comment, use `//`.

</Accordion>

<Accordion title="E0004 — BLOCK_COMMENT_NOT_SUPPORTED">

**Cause:** A `/* … */` style block comment was found. Volan only supports line comments (`//`) and doc comments (`///`).

```volan
/* ❌ block comment */
model User { … }
```

**Fix:** Replace with line comments.

```volan
// ✅ line comment
model User { … }
```

</Accordion>

<Accordion title="E0005 — MALFORMED_NUMBER">

**Cause:** A numeric literal could not be parsed — for example `1_` (trailing underscore), `0x` (incomplete hex), or `1.2.3`.

**Fix:** Correct the number literal to a valid integer or floating-point value.

</Accordion>

## Parser Errors (E01xx)

Parser errors occur when the token stream does not match the expected grammar. Volan attempts error recovery and may report multiple parser errors in a single pass.

<Accordion title="E0100 — EXPECTED_DECLARATION">

**Cause:** The parser expected a top-level keyword (`model`, `enum`, `datasource`, `generator`) but found something else.

**Fix:** Ensure every top-level item starts with one of the four supported keywords. Remove stray tokens.

</Accordion>

<Accordion title="E0101 — EXPECTED_NAME">

**Cause:** A declaration keyword was found but was not followed by an identifier.

```volan
// ❌
model {
  id Int @id
}
```

**Fix:** Provide a name immediately after the keyword.

```volan
// ✅
model User {
  id Int @id
}
```

</Accordion>

<Accordion title="E0102 — EXPECTED_OPENING_BRACE">

**Cause:** After the declaration keyword and name, `{` was expected but not found.

**Fix:** Add an opening brace after the declaration name.

</Accordion>

<Accordion title="E0103 — UNCLOSED_BLOCK">

**Cause:** A block was opened with `{` but the matching `}` was never found.

**Fix:** Add a closing `}` at the correct indentation level.

</Accordion>

<Accordion title="E0104 — EXPECTED_FIELD_TYPE">

**Cause:** A field name was found inside a model but no type followed it.

```volan
// ❌
model Post {
  title   // no type
}
```

**Fix:** Add the field type after the name.

```volan
// ✅
model Post {
  title String
}
```

</Accordion>

<Accordion title="E0105 — EXPECTED_EQUALS">

**Cause:** Inside a `datasource` or `generator` block, a config key was found but `=` was missing.

```volan
// ❌
datasource db {
  url "postgresql://…"
}
```

**Fix:** Add `=` between the key and value.

</Accordion>

<Accordion title="E0106 — EXPECTED_EXPRESSION">

**Cause:** An expression (string, number, boolean, env call, array) was expected but nothing valid was found.

**Fix:** Supply the missing value.

</Accordion>

<Accordion title="E0107 — UNCLOSED_ARGUMENT_LIST">

**Cause:** An attribute's argument list was opened with `(` but never closed.

```volan
// ❌
id Int @id(
```

**Fix:** Close the argument list with `)`.

</Accordion>

<Accordion title="E0108 — UNCLOSED_LIST">

**Cause:** An array literal `[…]` was opened but never closed.

**Fix:** Add a closing `]`.

</Accordion>

<Accordion title="E0109 — OPTIONAL_LIST_TYPE">

**Cause:** You wrote `Type[]?`. List fields cannot be optional.

```volan
// ❌
tags String[]?
```

**Fix:** Use `Type[]` (lists are always non-null).

```volan
// ✅
tags String[]
```

</Accordion>

<Accordion title="E0110 — NESTED_LIST_TYPE">

**Cause:** `Type[][]` (nested lists) is not supported.

**Fix:** Flatten to `Type[]`.

</Accordion>

<Accordion title="E0111 — REPEATED_OPTIONAL_MARKER">

**Cause:** `??` was written instead of a single `?`.

**Fix:** Remove the extra `?`.

</Accordion>

<Accordion title="E0112 — WRONG_ATTRIBUTE_FORM">

**Cause:** A field attribute `@attr` was used where a model attribute `@@attr` is required, or vice versa.

```volan
// ❌ @@unique is a model-level attribute
model User {
  email String @unique  // ✅ this is fine
  @@id([id])            // correct form
  @id([id])             // ❌ wrong form for model-level
}
```

**Fix:** Change `@` to `@@` or `@@` to `@` as appropriate.

</Accordion>

<Accordion title="E0113 — EXPECTED_ATTRIBUTE_NAME">

**Cause:** A bare `@` was found without a following identifier.

**Fix:** Add the attribute name, e.g. `@id`, `@default`.

</Accordion>

<Accordion title="E0114 — EXPECTED_ATTRIBUTE_MEMBER">

**Cause:** An attribute namespace prefix `@ns.` was found but no member name followed the dot.

**Fix:** Complete the attribute name, e.g. `@db.VarChar`.

</Accordion>

<Accordion title="E0115 — EXPECTED_ARGUMENT_VALUE">

**Cause:** A named argument `name:` was found but no value followed.

```volan
// ❌
@relation(fields:)
```

**Fix:** Provide the argument value.

</Accordion>

<Accordion title="E0116 — UNEXPECTED_TOP_LEVEL_TOKEN">

**Cause:** A token that is not valid at the top level of a schema (e.g. a bare string) was encountered.

**Fix:** Remove the stray token or wrap it inside a block.

</Accordion>

<Accordion title="E0117 — EMPTY_MODEL">

**Cause:** A `model` block contains no field declarations.

```volan
// ❌
model Empty {}
```

**Fix:** Add at least one field.

</Accordion>

<Accordion title="E0118 — EMPTY_ENUM">

**Cause:** An `enum` block contains no values.

**Fix:** Add at least one enum variant.

</Accordion>

<Accordion title="E0119 — EXPECTED_CONFIGURATION_VALUE">

**Cause:** A config entry inside `datasource` or `generator` has a key and `=` but the value is missing or invalid.

**Fix:** Supply a valid value: a string, `env("VAR")`, or an array of strings.

</Accordion>

<Accordion title="E0120 — ATTRIBUTE_NOT_ALLOWED_HERE">

**Cause:** An attribute was placed in a context that does not accept it (e.g. a block attribute inside a `datasource` or `generator` block).

**Fix:** Remove the attribute or move it to a supported context.

</Accordion>

<Accordion title="E0121 — UNEXPECTED_TOKEN_IN_BLOCK">

**Cause:** A token that is not valid inside the current block type was found.

**Fix:** Remove the token or ensure it belongs inside the current block.

</Accordion>

## Semantic Errors (E02xx)

Semantic errors are reported after the schema parses successfully. They represent logical or type-level inconsistencies that make the schema invalid.

### Declarations and Naming

| Code | Name | Description |
|------|------|-------------|
| `E0200` | `DUPLICATE_DECLARATION` | Two top-level declarations (models or enums) share the same name |
| `E0201` | `UNKNOWN_TYPE` | A field's type is neither a scalar, an enum, nor a model defined in this schema |
| `E0202` | `DUPLICATE_MEMBER` | Two fields of one model, or two values of one enum, share a name |

### Datasource and Generator Configuration

| Code | Name | Description |
|------|------|-------------|
| `E0203` | `MISSING_DATASOURCE` | The schema has no `datasource` block |
| `E0204` | `DUPLICATE_DATASOURCE` | The schema has more than one `datasource` block |
| `E0205` | `UNKNOWN_PROVIDER` | The `provider` names a database Volan does not support |
| `E0206` | `MISSING_OPTION` | A `datasource` or `generator` block is missing a required property |
| `E0207` | `UNKNOWN_OPTION` | A `datasource` or `generator` block declares a property that has no meaning there |
| `E0208` | `INVALID_OPTION_VALUE` | A configuration property has a value of the wrong kind |

### Identity and Primary Keys

| Code | Name | Description |
|------|------|-------------|
| `E0209` | `MISSING_PRIMARY_KEY` | A model declares no primary key — every model must have exactly one `@id` or `@@id` |
| `E0210` | `DUPLICATE_PRIMARY_KEY` | A model declares its primary key more than once |
| `E0211` | `INVALID_ID_FIELD` | A field cannot be part of a primary key (e.g. it is a relation or list field) |

### Attributes

| Code | Name | Description |
|------|------|-------------|
| `E0212` | `UNKNOWN_ATTRIBUTE` | An attribute name is not one Volan recognises |
| `E0213` | `UNKNOWN_ATTRIBUTE_ARGUMENT` | An attribute was given an argument it does not accept |
| `E0214` | `MISSING_ATTRIBUTE_ARGUMENT` | An attribute is missing a required argument |
| `E0215` | `INVALID_ATTRIBUTE_TARGET` | An attribute cannot be used on this kind of field or block |
| `E0216` | `DUPLICATE_ATTRIBUTE` | The same attribute was applied to a field or block more than once |
| `E0231` | `UNKNOWN_ATTRIBUTE_NAMESPACE` | A native-type attribute uses a namespace other than `db` (e.g. `@pg.VarChar` instead of `@db.VarChar`) |

### Defaults and Field Constraints

| Code | Name | Description |
|------|------|-------------|
| `E0217` | `INVALID_DEFAULT` | A `@default` value does not fit the field it is on — for example, a string default on an `Int` field, or `autoincrement()` on a non-integer field |
| `E0218` | `INVALID_UPDATED_AT` | `@updatedAt` is on a field that is not `DateTime` |
| `E0229` | `INVALID_UNIQUE_FIELD` | `@unique` is on a field that cannot carry it (e.g. a list or relation field) |
| `E0230` | `EMPTY_FIELD_LIST` | A `@@unique` or `@@index` constraint was declared over an empty field list |

### Relations

<Accordion title="E0219 — UNKNOWN_FIELD_REFERENCE">

**Cause:** An attribute such as `@relation(fields: […])`, `@@unique([…])`, or `@@index([…])` names a field that does not exist on the model.

```volan
// ❌ — authorId is not declared
model Post {
  id       Int  @id @default(autoincrement())
  author   User @relation(fields: [authorId], references: [id])
}
```

**Fix:** Declare the missing field, or correct the name.

</Accordion>

| Code | Name | Description |
|------|------|-------------|
| `E0220` | `RELATION_MISSING_OPPOSITE` | A relation field has no matching field on the other model |
| `E0221` | `RELATION_AMBIGUOUS` | Several relation fields between two models could pair up, and no `@relation("Name")` disambiguator is present |
| `E0222` | `RELATION_ARGUMENT_MISMATCH` | `fields:` and `references:` in `@relation` do not have the same number of entries |
| `E0223` | `RELATION_INVALID_SIDE` | `fields:` and `references:` are on the wrong side of the relation, or are declared on both sides |
| `E0224` | `RELATION_REFERENCE_NOT_UNIQUE` | A relation points at fields that are not uniquely identifying on the referenced model |
| `E0225` | `RELATION_TYPE_MISMATCH` | A foreign key field has a different type from the field it references |
| `E0226` | `INVALID_REFERENTIAL_ACTION` | A referential action (`onDelete`, `onUpdate`) cannot be applied to this relation |
| `E0232` | `UNSATISFIABLE_REQUIRED_RELATION` | A model has a required relation to itself, so no row could ever be inserted |
| `E0233` | `RELATION_FOREIGN_KEY_NOT_UNIQUE` | The foreign key of a one-to-one relation is not marked unique, so it could point at one row from multiple rows |

### Mapped Names

| Code | Name | Description |
|------|------|-------------|
| `E0227` | `DUPLICATE_MAPPED_NAME` | Two models map to the same table name, or two fields of a model map to the same column name via `@map` |

## Warnings

Warnings do not prevent code generation but indicate patterns you should address.

<Accordion title="W0001 — DANGLING_DOC_COMMENT">

**Cause:** A `///` doc comment appears in the schema but is not immediately followed by a model, field, or enum declaration.

```volan
/// This comment is attached to nothing
// (blank line or end of file here)
```

**Fix:** Either attach the doc comment directly to a declaration or convert it to a regular `//` comment.

</Accordion>

<Accordion title="E0234 — CONNECTION_URL_IN_SCHEMA">

**Cause:** A literal database URL (containing credentials) is written directly in the schema file, which may be committed to source control.

```volan
// ⚠️
datasource db {
  url = "postgresql://admin:secret@localhost/prod"
}
```

**Fix:** Move the URL to an environment variable and reference it with `env()`.

```volan
// ✅
datasource db {
  url = env("DATABASE_URL")
}
```

</Accordion>

<Accordion title="E0228 — CASCADE_CYCLE">

**Cause:** An `onDelete: Cascade` chain forms a loop in the schema. This is allowed but may produce unexpected behaviour at runtime depending on your database's handling of cyclic cascades.

**Fix:** Review your referential actions and consider using `Restrict` or `SetNull` to break the cycle.

</Accordion>
