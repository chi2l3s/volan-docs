When you need computed statistics rather than individual rows, Volan provides two dedicated query methods: `aggregate { }` for whole-table or filtered aggregations, and `groupBy { }` for bucketing rows by one or more field values before aggregating. Both methods are type-safe — result properties are generated from your schema, so there is no stringly-typed column access.

## `aggregate { }`

The `aggregate { }` method computes one or more aggregate functions over the matching rows and returns a single result object. You opt into each function individually; Volan only requests the computations you ask for.

```kotlin
val result = db.post.aggregate {
    where { draft eq false }
    count()
    sum { views }
    average { views }
    minimum { createdAt }
    maximum { views }
}
```

### Result properties

| Function called | Result property | Return type |
|---|---|---|
| `count()` | `result.count` | `Long` |
| `sum { views }` | `result.sumOfViews` | `BigDecimal?` |
| `average { views }` | `result.averageOfViews` | `Double?` |
| `minimum { createdAt }` | `result.minimumOfCreatedAt` | `Instant?` |
| `maximum { views }` | `result.maximumOfViews` | `Int?` |

`sum` always returns `BigDecimal?` and `average` always returns `Double?`, because the database widens these for precision. `minimum` and `maximum` return the field's own type as nullable (e.g. `Int?` for an `Int` field, `Instant?` for a `DateTime` field) because the result is `NULL` when no rows match. `count` always returns a non-nullable `Long` (returning `0` when no rows match).

<Warning>
  Accessing a result property for a function you did not request throws `VolanAggregateNotAskedException`. For example, reading `result.sumOfViews` when you only called `count()` will fail at runtime. Always call every aggregate function whose result property you intend to read.
</Warning>

### Examples

```kotlin
// Total published posts and average view count
val stats = db.post.aggregate {
    where { draft eq false }
    count()
    average { views }
}

println("Published posts: ${stats.count}")
println("Average views: ${stats.averageOfViews ?: 0.0}")
```

```kotlin
// Date range of all content
val range = db.post.aggregate {
    minimum { createdAt }
    maximum { createdAt }
}

println("First post: ${range.minimumOfCreatedAt}")
println("Latest post: ${range.maximumOfCreatedAt}")
```

## `groupBy { }`

`groupBy { }` partitions rows by one or more fields and computes aggregate functions within each partition. It is the equivalent of SQL's `GROUP BY … HAVING …` and returns a list of group result objects.

```kotlin
val groups = db.post.groupBy {
    by { authorId }
    count()
    sum { views }
    having { count gt 5L }
    orderBy { count.desc() }
    take = 10
}
```

### `by { }` — the grouping key

List the fields you want to group on inside `by { }`. You can specify multiple fields for a composite group key.

```kotlin
db.post.groupBy {
    by { authorId; categoryId }
    count()
}
```

### Aggregate functions

The same functions available in `aggregate { }` are available inside `groupBy { }`: `count()`, `sum { }`, `average { }`, `minimum { }`, `maximum { }`.

### `having { }` — filtering groups

`having { }` filters the group results after aggregation. The operators available here are the same ordered-field operators (`gt`, `gte`, `lt`, `lte`, `eq`, `between`, etc.) applied to computed aggregate values.

```kotlin
db.post.groupBy {
    by { authorId }
    count()
    sum { views }
    having { count gt 5L }          // only authors with more than 5 posts
}
```

You can combine multiple conditions in `having`:

```kotlin
having {
    count gte 3L
    sumOfViews gt BigDecimal("10000")
}
```

### Ordering and limiting groups

Use `orderBy { }` and `take` / `skip` on group results, exactly as you would on `findMany`:

```kotlin
db.post.groupBy {
    by { authorId }
    count()
    sum { views }
    orderBy {
        sumOfViews.desc()
        count.desc()
    }
    take = 20
}
```

### Accessing group results

```kotlin
val groups = db.post.groupBy {
    by { authorId }
    count()
    sum { views }
}

groups[0].authorId    // Int  — the grouped-by field value
groups[0].count       // Long
groups[0].sumOfViews  // BigDecimal?
```

<Warning>
  Accessing a field that was not listed in `by { }` on a group result object throws at runtime. For example, if you grouped only by `authorId`, reading `groups[0].categoryId` will fail. Stick to the fields you declared in `by { }` and the aggregate properties you requested.
</Warning>

### Full example

```kotlin
// Top 10 authors by total views, among those with more than 5 published posts
val topAuthors = db.post.groupBy {
    by { authorId }
    count()
    sum { views }
    average { views }
    having { count gt 5L }
    orderBy { sumOfViews.desc() }
    take = 10
}

topAuthors.forEach { group ->
    println(
        "Author ${group.authorId}: " +
        "${group.count} posts, " +
        "${group.sumOfViews} total views, " +
        "${group.averageOfViews?.let { "%.1f".format(it) }} avg"
    )
}
```
